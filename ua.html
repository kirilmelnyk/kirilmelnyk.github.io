Кейс · Логістика

Автоматизація відправлень Нової Пошти

Telegram · розбір ШІ · пакетні ТТН · бойова система

Проблема
Заявки приходили вільним текстом у Telegram. Адреси й накладні опрацьовували по одній вручну, а помилка в сумі чи сорті коштувала грошей.
Зроблено
Багаторівневий розбір заявок, перевірка адрес через API Нової Пошти, пакетне створення ТТН для трьох контрагентів з окремими ключами, розділення на місця за лімітом 25 кг, об'ємна вага, реєстри та картки для друку.
Результат
280 ТТН за два дні. Тестовий реєстр на 319 ТТН прийнято Новою Поштою. Кожну зміну правил перевіряю на 87–280 реальних заявках.
Моя роль
Вимоги, правила ризиків, тестування на реальних даних і на тестовому акаунті Нової Пошти, приймання результату. Код написано з Claude Code.

Проблеми, розібрані до першопричини

Обʼєднання падало лише на продакшені

Причина
MySQL 8.4 відхиляє шлях JSON-ключа без лапок. Тести йшли на MariaDB і цього не показали.
Рішення
Ключ узято в лапки, тести перенесено на MySQL 8.4.

Продакшен упав при зелених тестах

Причина
Виклик, застарілий у PHP 8.5, став фатальною помилкою лише на сервері.
Рішення
Виклик прибрано й додано охоронний тест на застарілі функції.

Telegram-бот замовк

Причина
Telegram змінив ID групи, коли чат став супергрупою.
Рішення
Бот тепер автоматично відстежує міграцію чату.
