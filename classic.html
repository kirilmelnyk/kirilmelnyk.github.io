Case · Logistics

Nova Poshta shipment automation

Telegram · AI parsing · bulk waybills · live system

Problem
Orders arrived as free text in Telegram. Addresses and waybills were handled one by one by hand, and a typo in an amount or variety cost money.
Built
A layered parser, address checks against the Nova Poshta API, bulk waybills (TTN, the Ukrainian bill of lading) for three counterparties with separate keys, seat splitting by the 25 kg limit, volumetric weight, registries and print cards.

My role

Problems traced to the root cause

Merge failed on production only

Cause
MySQL 8.4 rejects an unquoted JSON key path. Tests ran on MariaDB and hid it.
Fix
Quoted the key and moved the tests to MySQL 8.4.

Production crashed with green tests

Cause
A call deprecated in PHP 8.5 became a fatal error on the server only.
Fix
Removed the call and added a guard test for deprecated calls.

The Telegram bot went silent

Cause
Telegram changed the group ID when the chat became a supergroup.
Fix
The bot now follows the chat migration automatically.
